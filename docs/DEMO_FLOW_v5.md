# JurisTwin Championship v5 — Judge Demo Flow

## 0:00–0:25 — Establish the problem

Open **Overview**.

Point only to the headline and the exposure count:

> One policy contradiction is exposing 27 customers.

Do not explain the architecture yet.

## 0:25–1:15 — Let the judge challenge the system

Click **Judge input**.

Ask for an unseen policy sentence, or use a judge-provided TXT/EML/JSON file.

The key output is:

- contradiction verdict;
- exact policy-atom collision;
- quarantine state;
- BFS blast radius.

## 1:15–2:00 — Prove the contradiction

Open **Conflict map**.

Explain the central governed rule and the contradicting evidence. Drag one evidence node to prove the graph is live; the connected edges should move with it.

## 2:00–3:00 — Test the future

Open **Digital twin**.

Run the 1,500-scenario test. Compare A, B and C quickly. The judge should only need to see:

- fit score;
- delay;
- complaint probability;
- policy alignment;
- robustness certificate.

## 3:00–4:00 — Govern the change

Send Option C to governance.

Explain that the backend refuses publication unless authority, impact, robustness, ledger and security checks pass.

Approve and publish.

## 4:00–5:00 — Prove and attack

Open **Assurance**.

Build the signed Decision Assurance Proof Pack, then run **Attack Sentinel**.

End on the adversarial pass result and the zero persistent mutation result.

## Closing sentence

> JurisTwin stops an organisation from contradicting itself — before the contradiction reaches the customer.
